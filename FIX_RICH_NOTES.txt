FIX_RICH_22 — HostedBot lifecycle + pm2 subprocess.run blocking the event loop (CRITICAL)
------------------------------------------------------------------------------------------------
Files: hosting_panel_bot.py, approval_bot.py
Root cause: FIX_RICH_17 (round 3) only wrapped is_running()/get_logs() in asyncio.to_thread().

  1. do_action (hosting_panel_bot.py) — start/stop/restart branches

  3. cb_handler env_restart branch (hosting_panel_bot.py)
  4. cb_handler admin_delall branch (hosting_panel_bot.py) — per-bot stop+delete loop
  5. cb_handler admin_force_stop branch (hosting_panel_bot.py)
  6. cb_handler admin_force_del branch (hosting_panel_bot.py)
  7. cb_handler admin_shutdown branch (hosting_panel_bot.py) — subprocess.run(["pm2","stop","all"])
  8. admin_server_stats (hosting_panel_bot.py) — subprocess.run(["pm2","jlist"])
  9. resource_monitor_worker (hosting_panel_bot.py) — subprocess.run(["pm2","jlist"]) AND the
     restart-on-exceed call, both in the same background loop
 10. execute_approval in hosting_panel_bot.py (b.start()) AND execute_approval in approval_bot.py
     (start_pm2(...) — start_pm2's internal sync SQLite/file I/O now simply executes inside the
     to_thread worker thread; no changes needed inside start_pm2 itself)

FIX_RICH_26 — plain-text credit footer / no Telegram link preview
------------------------------------------------------------------
Files: hosting_panel_bot.py, approval_bot.py

Root cause: credit_footer() returned an HTML <a href="https://t.me/..."> anchor.
That made the username clickable and caused Telegram to generate a link-preview card.

Fix: credit_footer() now returns only plain text:
    👑 Bot by @<username>
No t.me/ URL and no <a href> tag remains in the returned footer.

FIX_RICH_27 — rich card persistence after button taps
------------------------------------------------------
Files: hosting_panel_bot.py, core/rich_message.py

Root cause: Bot API 10.3 rich-message edit counterparts were unreliable, so the
rich wrapper fell back to safe_edit(), replacing the rich card with ordinary PTB UI.

Fix: _rich_edit_with_fallback() now best-effort deletes the previous message and
sends a fresh rich card with sendRichMessage. The is_media parameter remains in the
function signature for call-site compatibility. core/rich_message.py now provides
delete_message(). edit_blocks() remains available for future use.

Preservation
------------
- Existing FIX_RICH_1..25 markers were preserved.
- Existing callback_data values were not renamed or removed.
- No _rich_edit_with_fallback call sites were changed.
- safe_edit() fallback behavior was left intact.
- edit_blocks() remains in core/rich_message.py.

Verification
------------
- py_compile passed for all three Python files.
- rich_message.delete_message import/attribute check passed.
- hosting_panel_bot.py callback_data count remains 100.
- No credit_footer anchor return remains in either bot.
- No `t.me/{username}` remains in either credit footer.
